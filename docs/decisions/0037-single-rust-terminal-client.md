# ADR 0037: one Rust terminal client

Date: 2026-10-22. Status: accepted at the owner's request. Amends [ADR 0020](0020-capability-catalog-and-tui.md) (the terminal client and how its parity with the desktop is held) and [ADR 0029](0029-rust-terminal-workbench.md) (the Node bridge behind the Rust workbench). The capability catalog, the runtime's authority and every product rule are unchanged.

## Context

The terminal client was two programs. `packages/tui` (Node) carried the command line, the command table, the request builders, the failure explanations and the formatting, through the shared TypeScript `@luuna/api-client`; the Rust workbench of ADR 0029 drew the interactive screens and ran every action through that Node program as a child process over a JSONL bridge. Node was therefore a prerequisite of `lu`, and the installer staged the Node package, a compiled copy of the API client and the catalog beside the executable. The owner asked for the whole client to be rewritten in Rust or Go with nothing of its behaviour changed: functionality, interactions and commands.

## Decision

1. **Rust, one executable.** `crates/luuna-tui` is the entire client. Rust was chosen because the workbench, the runtime and the workspace already are; the workbench's state, screens and terminal handling are kept as they were. `luuna-tui <command>` runs one cataloged action, `luuna-tui` alone on a terminal opens the workbench, and `scripts/start-terminal.ps1` (behind `lu` and `luuna`) runs the executable directly. `packages/tui` is removed; the desktop keeps `@luuna/api-client`.
2. **The workbench's actions run in process.** `bridge.rs` is an in-process service that speaks the same versioned protocol the Node bridge spoke (requests `catalog`, `invoke`, `read`, `guide`, `reply`, `abort`, `shutdown`; the same events, limits, prompts, outcome classes, health polling and token redaction), so the workbench's reducer and its tests are unchanged.
3. **The command table is data.** `crates/luuna-tui/commands.json` holds every command's name, action label, context, arguments, flags, descriptions, prompts and parity example, generated from the former JavaScript table so every string is unchanged. The executable embeds it, and `scripts/check-contracts.mjs` reads it to trace commands to the catalog and now also asserts one command per catalog entry, named as the catalog names it (the former JavaScript parity test).
4. **JavaScript semantics where output depends on them.** `js.rs` is a JSON value with the original client's semantics: insertion order with integer-like keys first, `undefined` omitted from JSON, numbers printed like `Number.prototype.toString`, `String()` coercion, UTF-16 string lengths and slices, and V8's `JSON.parse` error messages. Formatters fail where the original read a field of a missing value, so a malformed response still produces the same refusal. serde_json's order-preserving feature is not enabled: it would change ordering across the workspace, including the runtime's canonical hashing.
5. **No new dependencies.** The runtime listens on loopback only (ADR 0011), so the client speaks plain HTTP/1.1 over tokio's TCP (the existing `tokio` dependency gains its `net` feature; `Cargo.lock` is unchanged). The original's regular expressions are ported as explicit matchers.
6. **`init` replaces `prime`.** At the owner's request the guided setup is `lu init` (`luuna init`); `lu prime` no longer exists. The guide screen's header reads INIT. The component CLIs' own `prime` commands, which the guide's agents step runs, are unrelated and unchanged.

## Consequences

Node is no longer a prerequisite of the terminal client (it still is of the pinned Pi engine and of the desktop's build), and the installer's terminal payload is `luuna-tui.exe` alone. Parity between the desktop and the terminal is no longer held by one shared module: the desktop uses `@luuna/api-client`, the terminal its Rust port of the same client, failure explanations, request builders and projections. It is held instead by `scripts/check-contracts.mjs`, by Rust tests that assert request bodies and refusal sentences, and by the differential evidence below. A change to the shared client's behaviour must now be made in both places; the contract check catches catalog drift, not behavioural drift, so such a change also needs its Rust test.

Behaviour was ported exactly, including one defect that existed before: `export-user-memory --output <file>` without `--json` writes the file and then reports a failure, because the original formatter read `memory.length` of the written summary. It is preserved here, not fixed silently.

## Evidence

- A differential harness ran the frozen JavaScript client and the Rust client side by side, with the same argv, environment and standard input, against one mock runtime: every catalog command and both projections under sixteen response modes (realistic records, empty, null, array, string and number bodies, an unreadable body, 409, 422 with and without a runtime reason, 503, 500, 401, 403, 404, 429), with and without `--json`, plus about ninety hand-written cases (help and dispatch, connection and URL variants, usage errors, refusals, request-body edge cases, documents on standard input, the plan legacy retry, follow with an outage, paged events). Each case compared exit code, stdout, stderr, files written and every HTTP request (method, path, query, headers, body). Help cases normalize only the `prime`/`init` rename, and the working directory's path is replaced by `<cwd>`. Result on Windows, 2026-10-22: 1419 of 1419 cases identical. The first run found three real differences, all fixed before the final run: the help's non-breaking space before each `·` of the component key lists, Node's resolved absolute path in file-error messages, and V8's wording of the after-JSON parse error.
- `node scripts/tui-smoke.mjs --runtime target/debug/luuna-runtime.exe` against a disposable runtime with the synthetic Pi fixture: 51 of 51 checks passed (import, discovery, manifest confirmation, a real baseline, ticket, plan, exact-hash approval, writer, candidate, diff, validation, a hard kill during a held check with the live follower receiving all 49 events in order across the restart, recovery, orderly shutdown). Synthetic evidence, never provider evidence.
- `cargo test -p luuna-tui`: unit tests for the JSON model, text layout, URL parsing, failure matchers, builders, formatters and the guide; `tests/cli.rs` (catalog parity against the built executable, bodies, refusals, approval, usage, follow, help), `tests/guide_flow.rs`, `tests/bridge_service.rs`, and the real-PTY `tests/terminal_lifecycle.rs` and `tests/guide_pty.rs`.
- `npm run test:contracts`, `npm run test:tui-terminal`, the API client and desktop suites.
- `node scripts/tui-native-audit.mjs` (ConPTY, Windows 11): 81 checks passed, 0 failed, UI coverage complete. One check could not run on the audit host: warm reuse through the production PowerShell bootstrap, because the owner's own runtime held port 4242.
- Linux (WSL Ubuntu, rustc 1.90, Node 22): `cargo test -p luuna-tui` passed, `tui-smoke` passed 51 of 51, and the differential harness found 1419 of 1419 cases identical. The oracle loaded the frozen API client's compiled `dist`, because that Node build has no TypeScript support. The first Linux run found one real platform difference, now fixed: on POSIX, Node's file-error messages name the path as given; only on Windows do they name the resolved absolute path.

- `scripts/package-windows.ps1` (release profile, 2026-10-23) built the unsigned development installer `Luuna_0.1.0_x64-setup.exe`. Its terminal payload is `luuna-tui.exe` alone, the staged executable answered `--help`, and the packaged-layout verification passed, including the component digests. That build preceded the Orbit merge below, so it has no `luuna-sbx.exe`.

## Merge with Orbit (ADR 0036)

[ADR 0036](0036-orbit-and-project-sandbox.md) landed on `main` while this rewrite was in progress. It added the commands `orbit`, `orbit-exec`, `orbit-run`, `orbit-sync` and `sbx` to the JavaScript client this ADR removes. Merging the two ported them into the Rust client:
- `commands.json` gained their entries unchanged, generated from the merged JavaScript table. Two fields were added: `rest` (a trailing command taken verbatim) and `failed: "orbit"` (exit 1 when a repository failed or was blocked); the bridge's catalog omits `failed`, as the original did.
- `format.rs` gained the three Orbit formatters.
- `sandbox.rs` hands the plan to `luuna-sbx` exactly as `sandbox.mjs` did: in the launcher's environment, without the runtime token or URL. The launcher is found under `target/debug` in a checkout and beside the client in an installed layout.
- Exit codes widened to `i32`, so a sandboxed command's code passes through unchanged.

One behaviour was carried over as the original had it. In the workbench, an Orbit run in which a repository failed reports "The command failed." instead of the per-repository result, because the original bridge did so.

Evidence for the merge, 2026-10-23:
- The differential harness was re-run against the merged JavaScript client, with Orbit records, failure shapes and about 220 Orbit and sandbox cases added: 1639 of 1639 cases identical on Windows and on Linux (WSL). Help listings are compared without `init`, which only the Rust client has.
- An end-to-end run against a disposable runtime and the real AppContainer passed 9 of 9 checks: Orbit status, exec, exit 1 for a failed repository, the plan, a sandboxed `exit 7` returned as the client's exit code, the project readable inside the sandbox, and neither `LUUNA_API_TOKEN` nor `LUUNA_URL` present inside it. The grants were revoked afterwards.
- `cargo test -p luuna-tui` (Windows and Linux), `cargo test -p luuna-sandbox`, clippy, `cargo check --workspace --all-targets`, `npm run test:contracts` (64 actions), and the terminal, guard, component-pin, smoke-harness, API client, UI and desktop suites.

Not established here: the installer was not installed on a clean machine (the clean-machine procedure in `docs/PACKAGING.md` was not run), macOS was not exercised, and the Linux run was not a native tmux workbench audit.
