# ADR 0006: read-only repository import, machine registry and project event stream

Date: 2026-10-17. Status: accepted; amended 2026-10-21 (identity robustness, explicit rebind, registration overlap rules and inspection hardening; see the amendment below, which supersedes points 1, 2 and 4 where they differ).

## Context

M2a registers an existing repository, proposes its check recipes and persists a confirmed manifest without changing the developer's checkout. The current architecture separates the versioned manifest from machine-specific paths and requires that discovery propose commands rather than execute repository text. The event envelope and SQLite outbox were defined for runs, and project-level facts had no durable stream.

## Decision

1. **Inspection is read-only and executes nothing from the repository.** `luuna-git` shells out to the host `git` with `GIT_OPTIONAL_LOCKS=0`, `GIT_TERMINAL_PROMPT=0`, `--no-pager`, and `-c core.fsmonitor=false -c core.hooksPath=/dev/null`, every inherited `GIT_*` variable cleared, and every configured `filter.<driver>` clean/smudge/process command overridden to empty with `required=false`, so `status`, `rev-parse`, `rev-list`, `symbolic-ref`, `for-each-ref` and `remote get-url` leave the index and working tree byte-identical and cannot be redirected or made to execute repository-selected commands. Output is capped per stream while it is read. No fetch, push, checkout, hook or filter ever runs. Remote URLs are redacted (userinfo, query and fragment) before they are stored or returned.
2. **Repository identity** is the redacted `origin` fetch URL, the redacted push URL when it differs, and the sorted parentless commits reachable from HEAD (empty for shallow clones, which must then have a remote; more than 64 roots is rejected). Filesystem origins (paths or `file:` URLs) are machine-specific and are observed as no remote. Registration stores that identity; discovery and confirmation re-observe the path and reject a different repository at the same path with a conflict instead of silently re-binding. A repository without a portable remote carries an explicit `local:` identity in the manifest, and confirmation enforces that.
3. **The manifest is machine-independent and hashed with `luuna-json-v1`.** Local paths, observed commits, branches and dirty state live only in the private SQLite machine registry (`repositories` table) and in evidence records. `PlanRevision.manifest_hash` refers to this manifest hash.
4. **Discovery proposes; the developer confirms.** `luuna-discovery` reads a bounded set of well-known manifest files and proposes recipes as executable plus argument arrays with file-level evidence, observed/inferred confidence and open questions. Shell interpreters require an explicit `shell` capability, absolute executables are rejected, and the proposal is stored as a `Discovery` record, never executed. Confirmation requires the project's current revision, revision `n+1`, an identity match, the observed remote and an observed default branch, and records the exact HEAD commit per repository as the base.
5. **Project-scoped events reuse the run event envelope.** They are stored in `project_events` with their own monotonic sequence, `project_id` set to the project, and `run_id` set to the stream identifier `project:<project_id>`. Clients deduplicate and replay them with the same cursor rules as run events, and `manifest.confirmed` carries the complete manifest so replay reconstructs the confirmed map.

## Consequences

The routes `POST /api/v1/projects`, `GET /api/v1/projects[/{id}]`, `POST /api/v1/projects/{id}/discover`, `PUT /api/v1/projects/{id}/manifest` and `GET /api/v1/projects/{id}/events` implement the contract table in `docs/07-contracts.md`. `schemas/project.schema.json` gains an optional `cwd` per check (default `.`). Nothing in this slice enables repository writes, command execution or the storage guard's removal; M2b supplies the executor and baseline evidence, and M2c the approved writer. A multi-repository manifest is accepted by the contracts but relationships and integration remain M4 work.

## Amendment (2026-10-21): identity robustness, explicit rebind and inspection hardening

An audit found that legitimate changes made a registered project permanently unusable while the errors advised a re-registration the API refuses, and that parts of point 1 did not hold. The rules below keep rejecting a different repository at a registered path; they stop treating a machine-local spelling or a grown history as one, and give the developer an explicit, evented way to re-point a registration.

1. **Remote identity is the configured URL, compared by equivalence.** Inspection reads the first `remote.origin.url` and `remote.origin.pushurl` values instead of `git remote get-url`, which applies machine-local `url.<base>.insteadOf`/`pushInsteadOf` rewrites. Two remotes are the same when only their spelling differs: scp-like `user@host:/path` and `ssh://host/path` (also `git+ssh`/`ssh+git`), `http` and `https`, the user name, a default port, host case and a trailing `/` or `.git`. A different transport family (HTTPS versus SSH), host, non-default port or path is a different remote. Manifest confirmation compares the manifest's remote the same way, so the manifest stays machine-independent. A registration recorded earlier with a rewritten URL reports a mismatch once; a rebind (point 3) records the configured URL.
2. **A registered root set must be contained in the observed one.** Registration (and a rebind) still records the parentless commits reachable from HEAD, at most 64. Every later observation records the roots reachable from HEAD or any local branch (at most 4096) and must contain each registered root. Added roots, from a merge of unrelated history (`git subtree add`) or a checked-out orphan branch, are the same repository. A registered root that no local branch or HEAD reaches any more is a different repository or rewritten history and is rejected as before.
3. **An explicit rebind is the only way to change a binding.** `POST /api/v1/projects/{id}/repositories/{repository_id}/rebind` takes `{"local_path"?: "<absolute root>"}` (the registered path when omitted), inspects that checkout read-only and replaces the machine-registry entry. Sending the request is the developer's confirmation. It records `repository.rebound` with the old and new path and identity, the new observation and whether the confirmed manifest's remote still matches; an unchanged binding records nothing. It is refused while a run of the project is queued, running, exploring or implementing, because that work may be using the checkout. The manifest is not changed. Base commits, baselines and approvals stay bound to exact commits, and a manifest whose remote no longer matches must be confirmed again; confirmation enforces the match. Every identity-mismatch error names this route, and a vanished checkout's error names it with `local_path`. Archiving a project is still not implemented.
4. **A checkout is registered once and never overlaps Luuna's data directory.** Registration and rebind refuse a canonical path already registered by any project with 409. They refuse with 422, naming `LUUNA_DATA_DIR`, a repository inside the data directory (where Luuna-owned worktrees live) and a repository that contains the data directory (a runtime started inside the checkout would otherwise put its private database and worktrees there).
5. **Filters configured in submodules are neutralised too.** The `filter.<driver>` names are also collected from each populated submodule's own configuration, nested submodules included. Inspection finds the submodules from the index gitlinks with a streamed `ls-files --stage`, and refuses more than 256 populated ones; recorded but uninitialised submodules are not counted, because Git does not recurse into them. Submodules nested more than 8 levels deep are refused as well, because their drivers would be unknown. The names are passed as `-c` overrides, which Git propagates to the `status` it runs inside each submodule, so uncommitted submodule content still makes the checkout dirty. Configuration is listed with `-z`, so subsection names are read exactly. Git splits a `-c` setting at its first `=`, so no override can name a driver whose name contains `=`; such configuration is refused with a reason instead of being left to run.
6. **The output cap stops a command at once.** When either stream passes the cap, both reads end, the child is killed and the error is "git output too large". Registration and discovery return it as 422 with advice, instead of a 30-second stall reported as a timeout.
7. **Git's reason is kept.** A failed repository probe is "not a Git repository" only when Git says so. Git's dubious-ownership refusal is reported with advice to add the path to `safe.directory` in the developer's global configuration; Luuna never changes that setting. Any other failure carries Git's own message. Only the line terminator is removed from `--show-toplevel`, so a root whose name ends in whitespace is accepted.
8. **Branches are read by full reference name.** `symbolic-ref` and `for-each-ref` output is stripped of exactly `refs/heads/` or `refs/remotes/origin/`. A tag with a branch's name therefore no longer turns `main` into `heads/main` or hides origin's HEAD. Confirmation also accepts a default branch that exists only as an `origin/<name>` remote-tracking ref, as in a fresh clone.
9. **Discovery asks instead of overstating.** A recipe whose evidence file has uncommitted changes, or whose checkout has too many changed paths to tell, is downgraded to `inferred` and raises an `uncommitted-evidence` question: baselines and Luuna worktrees use HEAD, not the working tree. No question promises a testing-prerequisite task, because none is implemented. Instead, the questions tell the developer to add and commit tests and rediscover, or to confirm a required recipe for an existing command. The local-only remote question names the rebind needed after a URL remote is added. `GET /api/v1/projects/{id}/events` also accepts `?limit=1..10000`, and a cursor above `i64::MAX` is a 400, not a 500.
