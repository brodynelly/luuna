## Runtime component workflows, October 21, 2026

The owner requested actual application ticket, memory and prompt workflows using the separate public `luuna-missions`, `luuna-atlas` and `luuna-beacon` repositories. This change implements a bounded M6 slice, recorded in [ADR 0014](decisions/0014-runtime-component-workflows.md), on the existing uncommitted Windows checkout with pinned Rust 1.90.0 and Bun 1.4.3. It neither changes the component source pins nor publishes a package, commit or external resource.

Implemented behavior:

- Explicit per-project activation initializes managed private component stores and migrates existing tickets while preserving Luuna IDs, numeric revisions and creation timestamps. Incomplete activation is durably frozen and retried; enabled projects refuse missing/unavailable components without falling back to independent SQLite intent writes.
- Missions owns enabled ticket intent, criteria, status and dependencies through compatible CLI records. SQLite keeps the last reconciled projection and durable original delivery/source mapping. GET/list preserve a usable last-known view; the source endpoint reports current freshness and expected-revision reconciliation advances the projection after external changes. Plans, approval, implementation/repair and candidate evidence boundaries reject stale source assumptions; closed tickets/unresolved dependencies block work.
- Original create intent and attempted delivery are durable before the external call. Stable label plus envelope identity reconcile uncertain success, including removal of the label after creation. Missing identity after an attempted write or duplicate source identities fail closed. An original idempotency-key replay survives later source reconciliation without creating another record.
- Atlas application memory has explicit project/process/user scope and provenance; explicit user retrieval/selection is required. Beacon prompts support current-version preview, create and expected-version update. Selected exact memory/prompt snapshots and hashes become canonical plan inputs visible for exact-hash approval, then are re-observed before worker/evidence use. Imported developer/private stores do not enter context.
- The runner validates exact committed manifest/gitlink/source/package/Bun identity, uses a fixed bounded stdin bridge and sanitized native process environment, refuses links/reparse points and executable Atlas hooks, and stops owned descendants on errors/deadlines. It never treats prompts or host-native execution as an OS sandbox. Mission identity discovery uses scoped label/search commands; bound source and direct dependencies use public `show` commands rather than returning the entire store.

### Final component integration regression checks

The final source includes bounded component capture buffers on the heap and explicit runtime lock ownership. Native debug measurements showed the component-call future shrinking from 18,784 to 2,448 bytes (bounded reader: 8,264 to 96 bytes); a regression bounds these sizes. A parallel shutdown/reopen test exposed a separate inherited-descriptor lock race: closing a parent descriptor can leave a Unix flock held by a concurrent fork until exec. The final logical owner now explicitly unlocks before closing, and workers release their AppState before announcing completion. Exclusion remains intact across live clones; no startup retry or weakened ownership check was introduced.

## Desktop design system, October 21, 2026

The desktop client now follows one token-based design system ([DESIGN-SYSTEM.md](DESIGN-SYSTEM.md), [ADR 0013](decisions/0013-desktop-design-system.md)). It is presentation only: the runtime still decides every state, permission, reason and next step, and no render or enable condition, handler, visible text, label, aria value, heading level or smoke-read DOM order changed.

**Delivered.** The pieces:

- **Tokens.** `apps/desktop/src/design/tokens.css` defines the dark default and a full light scheme under `prefers-color-scheme`. Layered base and component sheets plus one token-only sheet per screen are bundled from `'self'` (Tauri CSP unchanged).
- **Tones and the badge.** Six outcome tones are carried by colour, a shape mark and the unchanged runtime text. Exhaustive `Record` maps from the api-client unions live in `design/tone.ts`, so a new runtime state fails the type check until it has a tone. Only passed evidence and a live connection are green: a completed demo session used to be painted green and is now neutral. Interruption and outages use their own tone, never danger. `StatusBadge` is the one chip.
- **Shared components.** Panel and subpanel spacing, tray, meta line, form group, field row, headed records, the reason and next-step pair, section disclosures, bounded scroll regions and empty states.
- **Accessibility.** WCAG AA in both schemes. The narrow layout keeps visual order equal to DOM order, and forced colours keep marks and selection.
- **Process.** Three independent proposals were scored by two judges, and four screen agents each applied the system to one screen. Two review rounds followed: dark, light and 760 px screenshots, a behaviour-preservation audit and a design-system code review. They found and fixed a base specificity bug (disabled inputs looked enabled), fields inheriting the label's weight, textareas ignoring `rows`, an empty field-row column, light surfaces that did not separate, stacked tone rules and hashes breaking with orphaned tails at 760 px. They also caught a vacuous enforcement design: Vitest returns `""` for `?raw` CSS, so the test reads stylesheets with `node:fs` and fails on an empty sheet.

**Enforcement.** `design/design-system.test.ts`, part of `npm test`, checks:

- token-only stylesheets: no colour, length or duration literals, no `opacity` or `!important`, approved media queries only;
- every `var()` resolves, and both schemes define the same colour roles;
- WCAG ratios for every semantic text, mark, border and focus pair in both schemes;
- no selector named after a runtime state, and tone variables read only under `[data-tone]`;
- shallow screen selectors, registered component files, heading levels, no inline styles, badges through `StatusBadge`, and dismissible alerts;
- the tone taxonomy itself.

`scripts/mvp-ui-smoke.mjs` gains a presentation audit on the reviewed walkthrough page, the recovery page and the offline page. It checks WCAG AA contrast of every visible text run, placeholders included, against its composited background in the dark and the light scheme, after colour transitions settle. It also checks that the client follows the system scheme and that nothing scrolls horizontally at the 760 px window minimum. Against the old dark-only stylesheet these checks failed: two text runs were at 4.15:1 and there was no light scheme.
