# Component library: forms and inputs (`packages/ui/src/forms/`)

Family 2 of [ADR 0034](../decisions/0034-owned-component-library.md), P1 and P2 items only. Existing `Button`, `TextField`, `TextArea`, `SelectField`, `Checkbox`, `Switch`, `Form`, `FieldRow`, `Actions` stay in `controls.tsx` and are not changed. These components reuse their class vocabulary (`quiet`, `button-md`, `.tone-mark`, `.visually-hidden`) and the same tokens, so they look identical. Styles: `forms/forms.css`, then `forms/pickers.css` (layer `components`, after `controls.css`).

Common behaviour: every labelled control gets a generated id (`useId`), a `name` (slug of the label unless given), `aria-describedby` for hint and error, `aria-invalid` when there is an error, and `aria-required` when required. `className`, `data-*` (including `data-capability`) and aria props pass through to the control (or the fieldset/group for group components). Controlled only. No `style`, no timers, no third-party imports. An error is a danger shape mark plus text; it never uses `role="alert"` (no Dismiss is needed because it is inline field text, announced politely through an always-present `aria-live="polite"` slot).

Helper modules (DOM-free, unit-tested): `listbox.ts` (`nextListState`, `filterOptions`, `firstActive`), `logic.ts` (`searchKeyAction`, `parseNumber`, `outOfRange`, `copyOutcome`), `identity.ts` (`fieldWiring`, `slugName`, `describedBy`).

Tone: tone is always carried by the shared `.tone-mark` element (shape) plus the text; this family has no CSS that maps tone names to colours. Only `Chip`, `IconButton`, errors and the copy failure show a mark.

Not covered by these tests: real focus behaviour, `aria-activedescendant` announcements, popup placement and both colour schemes in a real WebView. Unit tests render static markup and exercise the pure helpers; the repo has no DOM test environment.
